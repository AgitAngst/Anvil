# Anvil — командный центр Rust-разработок

> Статус: **K0, K1, K2, A0–A6 и Пульт П1–П7 пройдены** (П5 снят; Anvil 0.3.0 и `kit-v0.3.0` выпущены
> 27.09.2026) — общий вид `anvil-ui`, окно Anvil со списком проектов и их
> git-состоянием, сборка, тесты и запуск с логом, CI и выпуски с GitHub, `anvil-update` и соглашение о
> выпусках ([docs/RELEASES.md](docs/RELEASES.md)), установка, откат и удаление программ из окна, мастер
> выпуска; Tetrachrome, FFMincer и другие программы переведены на набор и обновляются сами; зависимости, RustSec,
> rustup и версия набора в каждой программе; палитра `Ctrl+K`, обзор `Ctrl+0`, уведомления Windows,
> строка удалённых серверов проекта; где остановились —
> в [HANDOFF.md](HANDOFF.md).
> Решения по бывшим открытым вопросам — в конце.
>
> Решено (23.09.2026): отдельный репозиторий; единый визуал для **всех** программ (общий крейт
> оформления); проверка обновлений — **внутри каждой программы** (общий крейт обновлений).
> Репозиторий Anvil — публичный. Вид набора — нейтральный «инструментальный»; сначала демо
> (`cargo run -p anvil-ui --example gallery --features demo`) — вид одобрен.

## Зачем

Сейчас каждая программа живёт своей жизнью: Tetrachrome, FFMincer и другие лежат в `D:\dev_personal`,
у каждой свой `target/release`, свой способ сборки, свой GitHub-репозиторий. Чтобы понять «что где
изменилось, что собрано, что выпущено и какая версия у меня стоит», приходится обходить всё руками.

Anvil — одно окно, в котором видно состояние **всех** Rust-проектов и из которого делается рутина:
собрать, запустить, обновить установленную копию, подтянуть зависимости, выпустить версию.

Не цель: IDE, редактор кода, замена git-клиента, CI-сервер. Anvil оркеструет `cargo`, `git`,
`rustup` и GitHub API — сам ничего из этого не переизобретает.

## Кто и где

- Один пользователь, Windows 10 x64, один `.exe` без установщика (как Tetrachrome).
- Rust + egui/eframe 0.36 — тот же стек, что у остальных программ.
- Отдельный репозиторий `AgitAngst/Anvil`: workspace из самого Anvil и двух общих крейтов
  (`anvil-ui`, `anvil-update`), которые подключают все программы — см. «Общий набор».
- `gh` нет, WSL/Docker нет. GitHub — через REST API с токеном (из `git credential fill` или keyring).

## Проекты под управлением

| Проект | Что это | Особенности |
|---|---|---|
| **Tetrachrome** | упаковщик каналов текстур, egui | один бинарник, портативный `presets.json` |
| **FFMincer** | конвертер аудио/видео поверх ffmpeg, egui | зависит от внешнего `ffmpeg` |
| *новые* | — | подхватываются автоматически |

Проекты находятся **сканированием корней** (по умолчанию `D:\dev_personal`): каталог с
`Cargo.toml` → проект; в workspace — перечисляются члены с `[[bin]]`/`src/main.rs`. Список можно
поправить руками (скрыть, переименовать, добавить путь вне корня) — правки в `anvil.toml`.


- **Слева** — список проектов, у каждого одна точка-состояние и один значок «что требует
  внимания» (грязное дерево, отстаёт от origin, красный CI, есть обновление, упала сборка).
  Сортировка — по последней активности.
- **Справа** — карточка проекта: ветка и git-состояние, версия из `Cargo.toml` и последний тег,
  CI, установленная версия, бинарники и запущены ли они, кнопки действий, вкладки с деталями.
- **Снизу** — полоса задач: текущая команда с прогрессом (cargo печатает `Compiling N/M` —
  из этого полоса), очередь, по клику раскрывается живой лог. Ошибки компилятора — кликабельны
  (открыть файл:строку в VS Code).
- **Обзор** (кнопка вверху или `Ctrl+0`) — сетка карточек всех проектов для взгляда «одним глазом».

### UX-правила

- Каждое действие — одна кнопка и одна строка в `Ctrl+K`-палитре («собрать lantern release»,
  «обновить tetrachrome»). Клавиатуры хватает на всё.
- Долгие операции никогда не блокируют окно; всё идёт в очередь задач, её можно отменить.
- Необратимое (push, тег, выпуск, удаление установленной версии) — только через окно
  подтверждения, где написано **что именно** произойдёт (команды, версия, ветка).
- Уведомление Windows по окончании долгой задачи, если окно не в фокусе.
- Никаких «молчаливых» провалов: любая ошибка — красным в полосе задач с кнопкой «лог».
- Светлая/тёмная тема, EN/RU — как в остальных программах.
- Состояние обновляется само: git и процессы — по изменению файлов (`notify`) и раз в N секунд,
  GitHub — раз в несколько минут и по кнопке ⟳.

## Возможности

### 1. Состояние (только чтение)
- git: ветка, чисто/грязно (сколько файлов), ahead/behind относительно origin (fetch по таймеру).
- Версия пакета, последний тег, коммитов после тега.
- CI: статус последнего прогона по ветке, ссылка на лог упавшей джобы.
- GitHub Releases: последний выпуск, его ассеты.
- Процессы: какие бинарники проекта сейчас запущены (PID, откуда — `target/release` или установка).
- Размер `target/` (с кнопкой `cargo clean`).

### 2. Сборка и запуск
- Собрать debug/release, конкретный бинарник или весь workspace; `cargo test`, `clippy`, `fmt --check`.
- **Заблокированный exe**: если бинарник запущен из `target/release`, Anvil не убивает процесс,
  а предлагает: собрать в отдельный `--target-dir`, или переименовать заблокированный exe (Windows
  это разрешает) и собрать заново, или «закрыть и перезапустить» — только по явному выбору.
- Запуск с аргументами (профили — например `lantern-desktop --profile x`), сохранённые «пресеты запуска».
- Ограничение параллельности (`-j`) — на большом workspace иногда кончается память линковщика.

### 3. Установка и обновление своих программ
Главное «обновление» — чтобы у меня всегда стояла свежая версия каждой программы, с откатом.
- Установка в `%LOCALAPPDATA%\Programs\<app>\<версия>\` + ярлык в «Пуск», активная версия — `current`.
- Источник: локальная release-сборка **или** ассет из GitHub Releases.
- «Обновить» = собрать/скачать → дождаться, пока программа закрыта (или предложить закрыть) →
  переключить `current` → по желанию запустить. «Откат» — на предыдущую версию.
- Бейдж «есть новее» в списке проектов.
- Та же схема установки, что у встроенного обновления программ (`anvil-update`): что бы ни
  поставило версию — Anvil или сама программа, — видно и откатывается одинаково.
- Данные программ (`%APPDATA%\…`, портативные файлы рядом с exe) Anvil не трогает никогда.

### 4. Зависимости и тулчейн
- Устаревшие зависимости: `cargo update --dry-run --verbose` (сам cargo знает, что обновится в рамках
  требований, а что держит новая мажорная версия; ничего ставить не нужно), разделение на
  совместимые, мажорные и «держат требования других пакетов»; прямые — отдельно от «по цепочке».
- `cargo update` (совместимые) — одной кнопкой, с прогоном тестов после и откатом `Cargo.lock`,
  если красно.
- Ломающие обновления — только список с changelog-ссылками; делаются руками/по команде.
- `cargo audit`-подобная проверка RustSec: архив `rustsec/advisory-db` в кеше, обновляется раз в сутки
  (с ETag), сверка идёт на месте — список зависимостей никуда не отправляется.
- `rustup`: текущий тулчейн, есть ли новый stable, обновить.
- Общая картина: где версии прямых зависимостей разошлись между программами; на каком теге набора
  Anvil каждая программа и «Поднять до свежего» (правка `Cargo.toml` и workflow, тесты, откат).

### 5. Выпуск версии
Мастер в несколько шагов, каждый видно и можно остановиться:
1. Проверки: дерево чистое, ветка синхронна с origin, тесты/clippy зелёные.
2. Новая версия (patch/minor/major или вручную) → правка `Cargo.toml` всех нужных крейтов.
3. Черновик заметок к выпуску из коммитов после прошлого тега (правится в окне).
4. Коммит `Release vX.Y.Z` → тег → push (подтверждение).
5. Для проектов с CI — ждать прогон и показывать ход; без CI — собрать локально и залить ассет
   в GitHub Release через API.

### 6. Быстрые переходы
Папка проекта, терминал в ней, VS Code, GitHub (репо/Actions/Releases), `HANDOFF.md`/`TODO.md`
проекта — в один клик. Для проекта с админкой серверов — её запуск (управление серверами остаётся там,
Anvil его не дублирует).

Палитра `Ctrl+K` (или поле в шапке): «Перейти» к проекту, его действия (запустить, собрать debug и
release, тесты, clippy, fmt, зависимости, выпуск, папка, терминал, VS Code, «Обновить X → версия»,
«Открыть админку») и общие (обзор, обновить всё, Rust и зависимости, лог, добавить папку,
настройки, обновления, о программе). Каждое слово запроса ищется в названии действия или имени
проекта; стрелки, Enter, Esc. «Собрать release» из палитры не трогает переключатель профиля.

## Общий набор: единый визуал и обновления

Anvil — не только окно, но и «фирменный набор» для всех программ. Два крейта в том же репозитории;
программы подключают их git-зависимостью по тегу:

```toml
anvil-ui     = { git = "https://github.com/AgitAngst/Anvil", tag = "kit-v0.1.0" }
anvil-update = { git = "https://github.com/AgitAngst/Anvil", tag = "kit-v0.1.0" }
```

Для правок набора «на живую» — локальный `[patch."https://github.com/AgitAngst/Anvil"]` на путь
`D:\dev_personal\Anvil\crates\…` в `.cargo/config.toml` программы (не коммитится). Anvil сам
показывает, какая версия набора у каждой программы, и умеет поднять её до свежей.

### `anvil-ui` — единый визуал

Основа — слой оформления самой зрелой из программ (две темы, контраст WCAG AA с тестом, векторные значки),
вынесенный в набор и очищенный от прикладного.

- **Токены**, а не цвета напрямую: фон, поверхность, карточка, разделитель, текст, слабый текст,
  акцент, успех / предупреждение / ошибка, выделение, фокус. Светлая и тёмная тема, выбор
  «как в системе / светлая / тёмная». Тест контраста 4.5:1 для каждой пары «текст–фон».
- **Типографика**: одни шрифты и шкала размеров (заголовок, подзаголовок, текст, подпись),
  полужирный — один на все программы.
- **Значки**: общий векторный набор (`icons::paint`), без картинок и шрифтов-иконок.
- **Виджеты**: основная / плоская / опасная кнопка, кнопка-значок, переключатель, секция, заметка,
  карточка, бейдж и точка-статус, полоса прогресса, всплывающее уведомление (toast), диалог
  подтверждения, пустое состояние, выпадающее меню, поле поиска, баннер обновления; с набора 0.8.0 —
  сегменты поровну, выпадающий выбор, ползунок, строки-переходы на страницы.
- **Каркас окна**: единые отступы, шапка, строка состояния, окно «О программе» (версия, ссылка,
  «проверить обновления»), окно настроек с общими пунктами (тема, язык, обновления).
- **Язык**: EN/RU для собственных строк набора; программа сообщает набору текущий язык.
- **Витрина**: `cargo run -p anvil-ui --example gallery --features demo` — все виджеты в обеих темах, чтобы
  править вид в одном месте и сразу видеть результат.
- Программа может **расширять** палитру своими токенами (у Lantern — подсветка найденного), но базовые
  берёт из набора.

Переезд программ:

| Программа | Что сделать |
|---|---|
| **Tetrachrome** | заменить свои `theme.rs` / `icons.rs` на набор, сохранив раскладку окна |
| **FFMincer** | сначала поднять egui 0.27 → 0.36, затем перевести на набор |
| **Anvil** | с первого дня на наборе — он же главный потребитель и проверка |

### `anvil-update` — проверка обновлений внутри программ

Каждая программа сама знает, что вышла новая версия, и умеет обновиться — даже без запущенного Anvil.

- **Когда**: при запуске (в фоне, не задерживая окно) и раз в сутки, пока программа открыта;
  плюс «Проверить обновления» в «О программе». В настройках: авто-проверка вкл/выкл,
  канал «стабильные / включая пред-выпуски».
- **Откуда**: GitHub Releases репозитория программы (`CARGO_PKG_REPOSITORY`), сравнение semver
  с `CARGO_PKG_VERSION`. Если выпуски вынесены в отдельный публичный репозиторий (например,
  `example/lantern-releases`), адрес задаётся программой при подключении крейта. Ничего, кроме этого запроса, программа наружу не шлёт.
- **Как выглядит**: ненавязчивый баннер из `anvil-ui` — «Вышла v0.3.1 · Что нового · Обновить ·
  Позже · Пропустить эту версию». Никаких модальных окон при запуске.
- **Как обновляется**: скачать ассет → сверить SHA-256 из `SHA256SUMS` выпуска → положить новую
  версию рядом → по согласию перезапуститься. Запущенный exe Windows удалить не даёт, но
  разрешает переименовать: старый → `*.old`, новый на его место, `*.old` убирается при следующем
  запуске. Если что-то пошло не так — остаётся рабочая старая версия.
- **Одна схема с Anvil**: если программа установлена через Anvil (`Programs\<app>\<версия>`,
  `current`), `anvil-update` ставит новую версию туда же — Anvil видит её и может откатить.
  Портативная копия (exe где попало) обновляется на месте.
- Данные и настройки программы обновление не трогает.
- Android-программы — вне этой схемы (там свой путь выпуска APK, см. [docs/ANDROID.md](docs/ANDROID.md)).

### Соглашение о выпусках

Общий контракт, на который опираются и Anvil, и `anvil-update`, и мастер выпуска:

- Тег `vX.Y.Z` (пред-выпуск — `vX.Y.Z-beta.N`).
- Ассет Windows: `<app>-X.Y.Z-windows-x64.zip` (внутри exe и всё нужное рядом).
- Файл `SHA256SUMS` в каждом выпуске.
- Заметки к выпуску — тело GitHub Release (их показывает «Что нового»).
- Программы с несколькими бинарниками (например, Lantern) — ассет на каждый пользовательский бинарник.
- Выпуски в отдельный публичный `<app>-releases`: CI репозитория программы публикует туда
  Release с ассетами и `SHA256SUMS` (нужен токен с правом записи в секретах CI).

## Устройство

```
Anvil/                       отдельный репозиторий AgitAngst/Anvil
  crates/
    anvil-ui/                единый визуал (см. выше)
    anvil-update/            проверка и установка обновлений
    anvil/                   само окно командного центра

crates/anvil/src/
    main.rs        окно, eframe
    ui/            список, карточка, обзор, палитра, полоса задач, мастер выпуска
    registry.rs    поиск проектов, anvil.toml, cargo metadata
    git.rs         состояние через `git` (CLI, не libgit2 — поведение как в терминале)
    github.rs      REST API: runs, jobs, releases, assets; токен из keyring / git credential
    jobs.rs        очередь задач: процесс, разбор вывода cargo (--message-format=json), отмена
    procs.rs       запущенные бинарники (sysinfo)
    install.rs     установка, current, откат, ярлыки (сама установка — из anvil-update)
    deps.rs        crates.io, RustSec
```

- Конфиг: `%APPDATA%\Anvil\anvil.toml` (корни, скрытые проекты, пресеты запуска, путь к VS Code).
- Кеш — папка `cache` рядом с `anvil.toml` (`deps.json`, `github.json`, архив RustSec, значок для
  уведомлений), чтобы окно открывалось мгновенно с последним известным состоянием, а свежее догружалось.
- Секреты (GitHub-токен) — только в keyring Windows.
- Anvil ничего не коммитит и не пушит сам по себе — только по кнопке с подтверждением.

## Решения по открытым вопросам (24.09.2026)

1. **Удалённые серверы проекта** — в Anvil очень коротко: одна строка в карточке проекта (имя сервера, работает
   ли, версия, сколько участников в сети, когда проверено). Подробности, SSH и управление — в
   админке проекта, её кнопка «Открыть админку» рядом (установленная — сразу, иначе сборка и
   запуск из проекта). Anvil сам к серверам не ходит: админка после каждой проверки пишет сводку
   `admin-servers.json` в своей папке настроек (без адресов и секретов), Anvil её читает.
2. **Корни сканирования** — по умолчанию только `D:\dev_personal`; другие папки добавляются в
   «Настройках» (и кнопкой «+» над списком). Папкой может быть и одиночный проект.
3. **Не-Rust проекты** — пока нет: Anvil только для проектов на Rust. Задел на будущее: поиск
   узнаёт вид проекта (Rust, Godot, Unity, просто git) и отбрасывает всё, кроме включённых в
   `anvil.toml` (`kinds = ["rust"]`); карточка у проекта без cargo показывает то, что есть (git,
   тег, CI, выпуски, заметки), с бейджем вида и без сборки, установки и зависимостей. Проверено
   вживую с `kinds = ["rust", "godot", "unity"]`.
   **27.09.2026 пересмотрено:** проекты Godot и Unity входят в библиотеку Пульта (0.3), по умолчанию
   `kinds = ["rust", "godot", "unity"]`.
