# Передача дел

Замысел и этапы — [SPEC.md](SPEC.md). Здесь — где остановились и как тут работать.

## Состояние (27.09.2026)

**K0, K1, K2 и A0–A6 пройдены**: репозиторий `AgitAngst/Anvil` (публичный), крейт `crates/anvil-ui`, витрина,
CI; крейт `crates/anvil` — окно командного центра со сборкой, запуском, CI и выпусками; крейт
`crates/anvil-update` и соглашение о выпусках (`docs/RELEASES.md`, общий workflow).

`anvil` (A0):
- `worker.rs` — фоновый поток: `registry::scan` → по проекту `cargo metadata --no-deps --offline`,
  `git::read`, заметки; процессы — каждые 3 с, git — каждые 20 с и при возврате в окно; `Cmd::Fetch` —
  `git fetch` всех параллельно. Окно только принимает `Event`, внешних команд не ждёт.
- `git.rs` — `status --porcelain=v2 --branch`, `log`, `describe --tags`, время `FETCH_HEAD`; разбор с тестами.
- `registry.rs` — поиск проектов (корень и его подпапки с `Cargo.toml`), главный пакет workspace —
  корневой или названный как папка.
- `procs.rs` — снимок процессов через Toolhelp (только Windows), совпадение по имени exe.
- `run.rs` — все внешние команды без окна консоли (`CREATE_NO_WINDOW`) и с `GIT_TERMINAL_PROMPT=0`.
- `config.rs` — `anvil.toml` (портативный рядом с exe или `%APPDATA%\Anvil`), первый запуск угадывает корень.
- `i18n.rs` + `lang/en.tsv` — строки Anvil через `t("…")`; тест ловит и пропущенные, и лишние.
- `ui/` — шапка (поиск, «Обновить» = перечитать + fetch, меню), список со сводкой, карточка проекта
  (Git, Версия, Бинарники; вкладки Коммиты / Изменения / Заметки), настройки (папки, скрытые, опрос origin).
- Значок exe, окна, трея и уведомлений — соты с фиолетовым ядром (с 29.09): PNG и SVG в `crates/anvil/assets/icon`
  (README там же), `build.rs` собирает ico и кладёт в `OUT_DIR` RGBA для окна и трея и PNG для тостов.
  `anvil_ui::appicon` остаётся для программ семьи (квадрат акцента со значком).

`anvil` (A1):
- `jobs.rs` — очередь задач в своём потоке, строго по одной: cargo с `--message-format=json`
  (единицы сборки → ход, `compiler-message` → ошибки с местом), stderr и прочий stdout — в лог;
  отмена — `taskkill /T /F` по дереву cargo; итоги тестов из «test result:». Шаги до команды
  (`Before::Stop`, `Before::MoveAside`) и запуск после успеха (`Spec::after`).
- `tasks.rs` — `Task` (сборка, тесты, clippy, fmt, clean, запуск бинарника) → `Spec`; занятый exe
  (`locked`: запущен из папки профиля) и три выхода (`Resolve`): отодвинуть exe, закрыть программу,
  собрать в `target/anvil`; цель главной кнопки (`run_target`: пресет → бинарник → первый).
- `launch.rs` — запуск отдельно от Anvil (`CREATE_NEW_CONSOLE`), остановка (закрыть как крестиком,
  через 5 с — принудительно), `move_aside` / `clean_moved` для `*.exe.old-<время>`.
- Число единиц сборки прошлого раза — `units.json` рядом с `anvil.toml` (полоса хода «N/M»).
- `ui/jobs.rs` — ход в строке состояния и панель лога (задачи слева; вывод и «Ошибки и
  предупреждения» справа, место ошибки открывается `code -g`); `ui/dialogs.rs` — занятый exe,
  остановка, `cargo clean`; `ui/presets.rs` — пресеты запуска. Настройки проектов (`release`, `run`,
  `presets`) и `build_jobs` (`-j`) — в `anvil.toml`.

`anvil` (A2):
- `github.rs` — свой поток: раз в 5 мин и по «Обновить» для каждого проекта с origin на GitHub —
  последние 10 прогонов Actions по текущей ветке (у упавшего последнего — упавшие задачи и шаги) и
  10 выпусков с файлами. `reqwest` (blocking, rustls), как у Amber.
- Токен: свой из keyring (служба `anvil`, пользователь `github`) → `git credential fill` с
  `GCM_INTERACTIVE=never` (без окон входа) → без токена (публичные, 60 запросов в час). Проверка —
  `GET /user`, в настройках видно, откуда токен, кто под ним и сколько запросов осталось.
- `ui/github.rs` — бейдж CI в заголовке, строки «CI» (Git) и «Выпуск» (Версия), баннер упавшего CI с
  «Открыть лог», вкладки «CI» (метка HEAD — прогон для твоего последнего коммита, по полному хешу) и
  «Выпуски»; упавший CI — красная точка в списке и строка в сводке.

`anvil-ui`:
- `theme.rs` — палитра-токены (`bg`, `surface`, `card`, `raised`, `hover`, `border`, `text`, `weak`, `faint`,
  акцент, `success`/`warning`/`danger`), акцент на программу (`Accent::VIOLET` — Anvil, `AMBER`, `TEAL` —
  Tetrachrome, `ROSE` — FFMincer, `BLUE` — прочие), шрифты (Segoe UI / Cascadia Mono), стиль egui.
  Акцент лежит в `ctx.data`, `Palette::of(ui)` собирает палитру из темы и акцента. Тест контраста.
- `icons.rs` — значки линиями в сетке 24×24.
- `widgets.rs` — кнопки (`Kind`), значок-кнопка, бейдж, точка, клавиша, карточка, баннер, пустое
  состояние, переключатель, сегменты, вкладки, строка навигации, поиск, прогресс, крутилка, меню,
  уведомления (`Toasts`), подтверждение (`confirm`).
- `chrome.rs` — панели окна (`top_bar`, `status_bar`, `side_panel`, `content`), знак программы,
  `dialog`, «О программе» (`about`), общие настройки (`CommonSettings`, `common_settings`).
- `lang.rs` — EN/RU для строк набора, язык системы по умолчанию; тест полноты словаря.
- `motion/` — движение: шкала, кривые, «меньше движения», эффекты и виджеты (Д1, ниже; описание — [docs/MOTION.md](docs/MOTION.md)).
- Фича `serde` — сериализация `CommonSettings`, `ThemeChoice`, `Lang`.

`anvil-update` (K1):
- `version.rs` — semver (`v1.2.3`, пред-выпуски, порядок); `releases.rs` — выбор самого нового выпуска
  новее текущего (черновики мимо, пред-выпуски по настройке), архив `<app>-X.Y.Z-windows-x64.zip` и
  `SHA256SUMS`; `install.rs` — расклад (портативный / `versions` + junction `current`, как для A3),
  скачивание, SHA-256, распаковка без выхода из папки, подмена файлов с откатом (`*.old-<время>`),
  установка версии с переключением `current`, перезапуск с теми же аргументами, уборка в фоне с
  повторами (прежний процесс ещё держит exe).
- `lib.rs` — `Updater` (состояние, `auto` при запуске и раз в сутки, `check`, `install`, `restart`,
  `dismiss`); без `SHA256SUMS` обновление не ставится. `ui.rs` — баннер (Вышла / Скачиваю / Установлено /
  Не удалось), окно «Что нового», строка для «О программе»; `lang.rs` — EN/RU своих строк.
- `CommonSettings.skip_version` в `anvil-ui` — «Пропустить эту версию».
- Пример `examples/updatable.rs` (флаги `--version`, `--repo`, `--api`): вся цепочка проверена вживую на
  подставном «GitHub» (`python -m http.server` с JSON выпуска, архивом и `SHA256SUMS`): баннер → «Что
  нового» → скачивание → подмена → перезапуск → уборка `.old`; и отказ при неверной сумме.
- `docs/RELEASES.md` — соглашение; `.github/workflows/rust-release.yml` — многоразовый выпуск
  (сборка, архив, `SHA256SUMS`, `gh release create`, заметки из аннотации тега); `release.yml` —
  выпуск самого Anvil по тегу `v*`. Шаги упаковки проверены локально; сам workflow запустится на
  первом теге.
- Anvil сам пользуется `anvil-update`: баннер над карточкой, статус в «О программе».

`anvil` (A3):
- `installs.rs` — установка бинарника: `%LOCALAPPDATA%\Programs\<бинарник>\versions\<метка>` + junction
  `current`, ярлык `%APPDATA%\…\Start Menu\Programs\<Имя>.lnk` (WScript.Shell через powershell, пути —
  через переменные окружения) на `current\<бинарник>.exe`; метка локальной сборки `версия-хеш[-dirty]`;
  уборка забытых временных папок старше 10 минут и `.<имя>.removed-*` при каждом перечитывании.
- Задачи: `Task::Install` (release-сборка → `jobs::InstallStep` → `install_version` → ярлык) и задача без
  процесса `jobs::Download` (архив выпуска + `SHA256SUMS` → `anvil_update::install::install_archive`; с
  токеном — адреса файлов в API, так видны и приватные выпуски; токен берёт сам поток задач).
- `ui/install.rs` — вкладка «Установка»: версия, «есть vX» (GitHub новее), «Из сборки · метка», «С GitHub ·
  vX» (только выпуск по соглашению), список версий с «Сделать текущей», «Запустить», папка, «Удалить…»
  (подтверждение; запущенную из установки — не удаляет). «⬆ vX» в списке проектов.
- `anvil-update::install` открыт наружу: `install_archive` (любой exe, `Source` с токеном), `versions`,
  `current_version`, `activate`, `uninstall`, `discard_dir` (переименовать в `.<имя>.removed-<время>` и
  стереть в фоне), `remove_dir_later`, `sweep_removed`.
- Проверено вживую: установка `demo` из сборки дважды, откат, удаление; установка Anvil v0.1.0 с GitHub,
  запуск установленной копии, удаление. После проверки ничего из установленного не осталось.

`anvil` (A4, мастер выпуска):
- `release.rs` — `bump`/`base` (от большей из версии Cargo и тега), `plan_edits` (toml_edit: версии
  пакетов, `workspace.package.version`, `version` у path-зависимостей, с сохранением оформления),
  `draft_notes`, `has_release_workflow`, `tag_exists`, `package` (архивы по соглашению + `SHA256SUMS`),
  `publish` (создать Release и залить файлы; `ANVIL_GITHUB_API` — только для проверок).
- `jobs::Step` — задача-сценарий: `Write`, `Run`, `Package`, `Publish`, до первой ошибки.
- `ui/release.rs` — мастер: Проверки → Версия → Заметки → Выпуск → Ход; режимы `Ci` (есть workflow:
  тег + push, дальше `github::Cmd::Watch` — прогон по тегу и Release раз в 15 с), `Upload` (сборка →
  архивы → коммит → тег → push → Release через API), `Local` (origin не на GitHub: архивы в
  `target/anvil-release`). Сборка — до коммита и тега.
- Проверено вживую на `demo` с локальным голым origin: режим `Local` (v0.2.1: Cargo.toml и Cargo.lock,
  коммит, тег с заголовками, push, архив, суммы) и `Upload` (v0.2.2: push в локальный репозиторий через
  `pushurl`, Release и файлы — на подставной API). Режим `Ci` вживую не запускался (нужен настоящий тег);
  его запросы (`actions/runs?branch=<тег>`, `releases/tags/<тег>`) проверены на v0.1.0 Anvil.

`anvil` (A5, зависимости и тулчейн):
- `deps.rs` — свой поток: `cargo update --dry-run --verbose` (разбор `Updating …` / `Unchanged … (available|
  latest: …)`), прямые зависимости из `cargo metadata --no-deps`, набор Anvil по источнику `anvil-ui` в
  `Cargo.lock` (`?tag=…#коммит`), `rustup check` и свежий тег `kit-v*` через `git ls-remote`. Итоги —
  `cache/deps.json` рядом с `anvil.toml`: при запуске сразу прошлое знание, в фоне — проверка того, что
  старше 12 ч или чей `Cargo.lock` менялся. `kit_edits` — перевод на тег набора (`toml_edit` по всем
  манифестам + `rust-release.yml@…` в workflow).
- `rustsec.rs` — архив `rustsec/advisory-db` (≈1 МБ) в `cache`, раз в сутки с `If-None-Match`; записи —
  TOML в начале markdown; `patched`/`unaffected` через `semver::VersionReq`; сверяются только пакеты с
  crates.io. `unsound` считается уязвимостью, `unmaintained`/`notice` — предупреждением.
- `jobs::Step::Snapshot` — запомнить файлы; упал шаг — вернуть. На нём «Обновить совместимые»
  (`cargo update` → `cargo test --workspace`) и «Поднять до kit-…» (правки → тесты).
- `ui/deps.rs` — вкладка «Зависимости» (RustSec, совместимые, мажорные, набор), окно «Rust и зависимости»
  (строка «Rust X» внизу боковой панели): тулчейн и «Обновить Rust», набор в программах, где разошлись
  версии; подтверждения со списком шагов. «RustSec» в списке проектов — при уязвимости.
- Проверено вживую на пробном `demo-deps` (regex 1.5.4, rand 0.7, набор kit-v0.1.0): находки, «Обновить
  совместимые» (regex → 1.13.1, тесты зелёные, отчёт перечитан), откат при падающем тесте (Cargo.toml и
  Cargo.lock байт в байт), «Поднять до kit-v0.2.0». На настоящих проектах — только чтение (dry-run).

`anvil` (A6, удобство):
- `ui/palette.rs` — палитра `Ctrl+K`: модальное окно сверху, строки собираются из проектов и общего;
  фильтр — каждое слово запроса в названии или имени проекта, начало слова выше (тесты). Стрелки и
  Enter перехватываются до поля ввода. Поле в шапке — кнопка-открывалка; фильтра списка больше нет.
  `App::start_task_as` — задача с явным профилем (`locked` помнит профиль).
- `ui/overview.rs` — обзор `Ctrl+0` / сегмент «Проект · Обзор» в шапке: карточки сеткой (до 4 в ряд),
  точка и бейдж как в списке, ветка, дерево, ↑↓, CI, последний коммит, запущенное, RustSec и
  обновления, точки серверов Amber. Щелчок — к проекту.
- `notify.rs` — тост WinRT (`windows` 0.62 с `UI_Notifications`, тот же крейт, что уже был в
  `Cargo.lock`): AUMID `AgitAngst.Anvil` в `HKCU\Software\Classes\AppUserModelId` (имя + PNG из
  `build.rs` в `cache`). Решает поток задач (`Notifier` в `jobs::Runner`): свёрнутое окно кадров не
  рисует. «Окно впереди» — `GetForegroundWindow` своего процесса, не свёрнуто и не консоль отладочной
  сборки. Порог — 15 с; настройка «Уведомлять о конце долгих задач» (`notify` в `anvil.toml`).
  `tasks::summary` — итог задачи словами для всплывашки и уведомления; ошибки считает `Outcome.errors`.
- `amber.rs` + `ui/amber.rs` — строка «Серверы Amber» у проекта с бинарником `amber-admin`: читает
  `admin-servers.json` (раз в 3 с смотрит время правки), «Открыть amber-admin». Сводку пишет
  `amber-admin` после каждой проверки и после «убрать сервер» (`write_summary`, репозиторий amber).
- Задел под другие проекты: `registry::Kind` (Rust/Godot/Unity/Git), `kinds` в `anvil.toml` (по
  умолчанию `["rust"]`), у не-Rust нет cargo, панели сборки, бинарников, вкладок «Установка» и
  «Зависимости»; бейдж вида в заголовке и в обзоре.

## Как здесь работать

- Живая проверка окна Anvil: в `target/debug/anvil.toml` лежит портативный конфиг (корень
  `D:\dev_personal`, тема, язык, выбранный проект) — `%APPDATA%` не трогается. Кнопки, вкладки и меню
  нажимаются через UI Automation: у кнопок Invoke, у вкладок и пунктов списка — Toggle; дерево
  AccessKit включается при первом обращении, поэтому поиск элемента — с повторами.
- В git Anvil только читает (`status`, `log`, `fetch`); коммитить и пушить он не должен без отдельного
  этапа и окна подтверждения. Программы останавливает только после подтверждения или явного выбора
  в окне занятого exe.
- Занятый exe: `target\<профиль>\name.exe` — жёсткая ссылка на `deps\name-<хеш>.exe`. Проверено
  вживую: после переименования запущенного exe cargo перекомпоновывает и кладёт новый, программа
  работает дальше.
- Живые проверки сборки — на пробном проекте в scratchpad (`projects/demo`, программа без окна, живёт
  30 с), а не на проектах пользователя; корень пробных проектов — во временном `target/debug/anvil.toml`,
  после проверки вернуть файл как был. Цепочку кнопок удобно прогонять скриптом: найти элемент по
  имени (Invoke / Toggle), подождать, снять окно.
- Снимок витрины скриптом: `Start-Process` витрины, ждать `Process.MainWindowHandle` **шире 600 px** (сначала winit отдаёт окно 16×16), `PrintWindow(hwnd, dc, 2)`, процесс убить по PID. Окно выше экрана не бывает — нижнюю половину длинной вкладки брать флагом витрины `--scroll px` (`WM_MOUSEWHEEL` через `PostMessage` не срабатывает).
- Снимки для README и `docs/` — только на выдуманных данных: репозиторий публичный, а часть проектов — нет
  (06.10 владелец попросил заменить настоящие). Витрина — как есть, её данные придуманы; окно самого Anvil —
  копия `anvil.exe` в scratchpad с портативным `anvil.toml` и пробными проектами с выдуманной историей (корень —
  через `subst`, чтобы в кадре был короткий путь; после снимка убрать).
- Строки для `t(...)` — без обратных слэшей: тест словаря читает исходник буквально.
- Python на Windows в текстовом режиме пишет CRLF: у Amber тест словаря читает многострочные строки
  буквально и спотыкается о `\r`. Правки скриптом — байтами, с `\n`.
- Проверочные программы — оконные (`windows_subsystem = "windows"`): у консольной снимок и UI
  Automation цепляются за окно консоли. Язык интерфейса Windows у пользователя английский —
  кнопки в UIA ищутся по английским подписям, если язык не задан явно.
- `Remove-Item` с путём из переменной и `*` защита не пропускает — удалять по `-LiteralPath` пофайлово.
- Свежие exe антивирус держит десятки секунд: удалить папку сразу после установки или запуска часто нельзя
  (ошибка 32), а через минуту — можно. Поэтому удаление — переименованием в сторону и стиранием в фоне;
  ничего не ждать в потоке окна.
- Живые проверки установки ставят настоящие папки в `%LOCALAPPDATA%\Programs` и ярлыки в «Пуск» — после
  проверки удалять через сам Anvil и сверять, что не осталось ни `.<имя>.removed-*`, ни `.lnk`.
- Весь диалог настроек на снимке виден, только если развернуть окно (UI Automation WindowPattern →
  Maximized): прокрутку egui через UIA не сдвинуть, а неактивный элемент не берёт фокус.

- egui/eframe 0.36 новее обучающих данных (`App::ui(&mut Ui)`, `egui::Panel`, `ctx.global_style()`,
  `Popup::menu`, `Modal`) — сверять с исходниками в `~/.cargo/registry/src/*/egui-0.36.2`.
- `cargo clippy` не пересобирает exe витрины — перед снимками `cargo build -p anvil-ui --example gallery`.
- Снимки окна — только `PrintWindow(hwnd, dc, 2)` по окну процесса витрины, не весь экран.
  Флаги витрины (`--dark`, `--settings`, …) открывают нужное без кликов; кнопку можно нажать через
  UI Automation `InvokePattern` по имени (AccessKit), так открывались меню.
- Строки набора — только через `tr(ctx, "…")` с русским ключом и переводом в `lang.rs`, иначе тест красный.
- Новые цвета — только токенами палитры; пары «текст–фон» добавлять в тест контраста.
- Правила вида — [docs/STYLE.md](docs/STYLE.md); меняешь значения или добавляешь виджет — поправь и его.
- Длинные Python-скрипты правок — файлом, не heredoc в Bash (heredoc ломается).
- `cargo fmt` — ширина 120 (`rustfmt.toml`); CI требует fmt, clippy `-D warnings` и тесты на Windows и Linux.
