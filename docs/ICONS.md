# Значки программ

Как делаются значки и знаки программ: от идеи до коммита. Собрано по работе 29.09.2026 над Anvil, Amber,
Morok, Tetrachrome и FFMincer — что получилось, что отвергли, какими приёмами пользовались и на какие грабли
наступали. Вид знака в самом интерфейсе (`chrome::app_mark`, `family::MARKS`) описан в [STYLE.md](STYLE.md);
здесь — сами значки (окно, панель задач, exe, трей, уведомления, телефон).

## 1. Коротко

- Значок — **самостоятельный знак с одной мыслью**: плоские цвета, без свечений и искр, читается в 16 px.
- Работа идёт **пачками**: 8–12 вариантов листом → выбор владельца → доводка → центровка → внедрение.
  Внедрять — только после слов «делай» или «внедряем»; пуш, тег, выпуск — только по команде.
- Каждый значок — **два SVG** (полный и мелкий), из которых **одна команда** собирает PNG и `.ico`.
- Знак в шапке и в «О программе» рисуется кодом программы по координатам мелкого SVG; «О программе» приходится
  собирать заново, потому что набор рисует там значок из `Icon`.
- Центровку смотрят глазом: для несимметричных знаков показывают 3–4 положения с осями через центр плитки.

(`Lock`, `Tiles`, `Film`), поэтому Пульт показывает их по-старому. Новые знаки — не линейные значки 24×24, набору
нужен способ хранить растровый или векторный знак программы; это правка набора и новый тег — только по команде.
STYLE.md (раздел про знак программы) описывает старое правило «квадрат акцента + значок набора»; для этих трёх
программ и для Anvil оно не действует.

## 3. Что предлагать и чего не предлагать

**Правила владельца** (нарушать нельзя):

- Значок не привязывают к другим программам семьи и к их палитре: «не привязывайся к моим текущим проектам, их
  будет больше». Знак держится сам по себе.
- **Никакой религиозной символики**: месяц и полумесяц, шестиконечная звезда, крест, пентаграмма и подобное
  («у меня ассоциации с исламом»). Такие идеи отсеиваются заранее, а не показываются «на выбор».
- Не «перегружено»: одна мысль, плоские цвета, без свечений, искр, лишних вырезов и деталей.
- Должно **читаться в 16 px** и хорошо смотреться на светлой и тёмной панели.

**Отвергнуто — не предлагать заново без причины:**

| Идея | Почему отвергли |
|---|---|
| Затмение, тёмный круг с кольцом и бликом | «похоже на камеру»; для VPN ещё и на веб-камеру |
| Капля или огонёк синего цвета | воспринимается как водяная капля |
| «M с огоньком» (буква, пламя, разрезы, свечение) | «перегружено» |
| Оптические иллюзии (треугольник Пенроуза, куб Неккера, ваза Рубина, сетка Германа, спираль и др.) | «это всё плохо, отказываемся от иллюзий» |
| Месяц с лицом в профиле | ассоциации с религией |
| Искра ✦ | читается как значок «ИИ» |
| Мясорубка, стейк, сосиски, тесак, «FF» из полос, ▶ нарезанный на полосы (первая пачка FFMincer) | пачка отвергнута целиком («эти не подходят»); в малых размерах эти образы и правда сливались |

**Что сработало** — простой геометрический знак с двойным смыслом:

- Tetrachrome: T — «тетра» (четыре квадрата), первая буква имени и четыре канала; цвета каналов взяты из самой
  программы (`src/theme.rs`), а альфа нарисована шахматкой, как в её предпросмотре.
- FFMincer: ▶▶ — «fast forward» и ffmpeg; нарезанная стрелка позади — «фарш» и след скорости.
- Morok: маршрут в виде M — сеть, путь, надежда (яркая точка в конце); сначала искали образ из шести смыслов:
  морок, VPN, защита, сеть, свобода, надежда.
- Anvil: соты вокруг ядра — «центр, на котором основано всё остальное».
- Amber: пузырь-реплика из янтаря — сообщение, застывшее в смоле.

**Что не сработало и почему** — полезно для оценки идей: ▶ из полос читается как «выровнять по левому краю»;
кадр с полосами внизу — как «капает краска»; хаб из узлов с яркой точкой сверху — как человечек, а его тонкие лучи
в 16 px пропадают; мост — как наушники.
Проверка одна: показать знак в 32 и 16 px и спросить себя, что это, не зная замысла.

## 4. Как вести работу

1. **Осмотреться.** `git status`, `git worktree list`, есть ли чужой план в `~/.claude/progress/<проект>.json`; как
   рисуется нынешний знак (`grep appicon`, `build.rs`, `src/icon.rs`); версия, тег набора, разрешения на коммит и пуш.
2. **Пачка.** 8–12 вариантов одним листом: значок 150 px, чипы 32 и 16 px на тёмной и светлой панели, отдельно 16 px
   по пикселям (увеличение без сглаживания). Подписи короткие, под листом — честная оценка: «сильные», «средние»,
   «слабые» и почему. Слабое называют слабым.
3. **Выбор.** «Запомни N» — сохранить SVG в память (не внедрять). «Доработай N» — 8 вариантов уточнений (цвет
   плитки, размер, зазоры, число деталей, светлая плитка) и мелкая версия у каждого. «Отвергнуто» — записать причину.
4. **Центровка** (раздел 6) — отдельный шаг, если знак несимметричен.
5. **Внедрение** — только по «делай». Программа со своим репозиторием — по шаблону из раздела 7; исключения —
   Anvil и Amber (раздел 8).
6. **Проверка** (раздел 9), коммит, отчёт. Пуш — по слову владельца; там, где у владельца стоит общее разрешение
   («коммиты и пуши — самому», Amber и Tetrachrome), — сразу. Тег и выпуск — только по слову.
7. **Долгие задачи** (внедрение с проверками — от ~15 минут) ведут на странице хода работы: скилл `progress`,
   `http://127.0.0.1:8765`; в рабочей сессии её не открывают.

## 5. Файлы значка

Один и тот же состав у Morok (`assets/brand`, файлы `morok*`), Tetrachrome и FFMincer (`assets/icon`, файлы
`<программа>*`):

| Файл | Что это |
|---|---|
| `<app>.svg` | Полный знак на плитке, viewBox 1024. Источник для 64 px и крупнее |
| `<app>-small.svg` | Упрощённый для 16–48 px: без тонких деталей, толще линии, шире зазоры |
| `<app>-{16,24,32,48}.png` | Из `-small.svg` |
| `<app>-{64,128,256,512}.png` | Из полного SVG |
| `<app>.ico` | Кадры PNG 16, 24, 32, 48, 64, 128, 256 (значок exe) |
| `README.md` | Что за знак, размеры, цвета, центровка, команда пересборки |
| `scripts/render-icon.ps1` | Рендер: `resvg` для PNG и упаковка `.ico` (PNG-кадры) на PowerShell; нужен `scoop install resvg` |

- Плитка — скруглённый квадрат (squircle) с вертикальным градиентом, один и тот же контур у всех программ; проще
  всего взять из готового SVG соседней программы.
- Знак лежит в группе `<g id="glyph" transform="translate(dx,dy)">`: сдвиг центровки записан прямо в файле.
- Плитка **одна для обеих тем**: значок приложения от темы не зависит. Светлую плитку показывают как вариант при
  выборе, но в программу идёт одна.
- Идентификаторы градиентов и масок не должны совпадать с `id` контура плитки (`bg`) — иначе `usvg` ругается.
- **Повторяемость проверяют хэшами:** второй запуск скрипта без правок SVG даёт те же байты.
- Мелкие размеры: 16, 24, 32 и 48 берутся из `-small`, от 64 — из полного. Виден ли знак в 16 px, решает
  просмотр по пикселям, а не в увеличении.

Приёмы упрощения для мелкого знака (взяты из работы): Morok — линия толще (26→70) и без пунктира; FFMincer — три
ломтика вместо четырёх и зазор шире; Tetrachrome — зазор 36 вместо 30 и меньше радиус; Anvil — плоское ядро и
ячейки без градиента.

## 6. Центровка на глаз

Знак, у которого «тяжёлая» часть в стороне, по габаритам кажется съехавшим. Считают так:

- вес пикселя = разность яркости с плоским цветом плитки (середина градиента), минус порог 0,06; свечения в счёт
  не идут;
- центр массы (`cx`, `cy`) и габариты видимых пикселей (вес выше 0,3 от максимума; `bx`, `by` — их центр);
- для симметричных знаков: `X = 0,4·cx + 0,6·bx`, `Y = 0,5·cy + 0,5·by`, цель — `(512, 506)` (чуть выше
  геометрического центра); сдвиг — разница цели и результата;
- для несимметричных знаков **показывают 3–4 положения** на одном листе с осями через центр плитки и полями
  слева, справа, сверху и снизу и просят выбрать; свой выбор называют.

Что выяснилось на практике:

- Morok: центр массы правее габаритов на ≈100 px (точка и толстая нога), а сама M симметрична. По габаритам
  долина буквы уходит левее оси, по оси знак кажется правее. Взято **вдвое короче сдвига до габаритов**
  («Середина»: −21, −40).
- FFMincer: целая стрелка тяжелее бледного следа. По габаритам она кажется правее, по яркой части знак уезжает
  левее. Взято по центру массы с небольшим уклоном к яркой стрелке (−12, −8).
- Тающие, полупрозрачные и тонкие части габариты обманывают — их вес считают по яркости, а не по площади.
- Одно положение для обеих тем и всех размеров, кроме мелкого: у мелкого версия своя, сдвиг считают отдельно.

## 7. Внедрение в программу (Rust, egui, `anvil-ui`)

Шаблон — Tetrachrome (один крейт) и FFMincer; у Morok то же самое по крейтам.

**Значок exe** — `build.rs` берёт готовый `.ico`:

```rust
let ico = PathBuf::from(std::env::var("CARGO_MANIFEST_DIR")?).join("assets/icon/<app>.ico");
println!("cargo:rerun-if-changed={}", ico.display());
if std::env::var("CARGO_CFG_TARGET_OS").as_deref() != Ok("windows") { return; }
let mut res = winresource::WindowsResource::new();
res.set_icon(ico.to_str().expect("utf-8 path"));
res.set("ProductName", "<App>");
res.set("FileDescription", "<App> — что делает");
if let Err(e) = res.compile() { println!("cargo:warning=exe icon skipped: {e}"); } // без rc.exe значка у exe не будет
```

`winresource` — build-зависимость (у Amber она появилась по слову «добавь зависимость»); `anvil-ui` и `image`
с `ico` из build-зависимостей убирают, если больше не нужны. У Morok значок ставят и у `morok-service`, и у
консоли `morok` — свой `build.rs` в каждом крейте.

**Значок окна** (`src/icon.rs`) — PNG 256 px в `egui::IconData`. Два способа:

- Если в программе уже есть `image` (Tetrachrome, Morok): `include_bytes!` и `image::load_from_memory`.
- Если декодера нет (FFMincer): `build.rs` читает PNG и пишет сырые RGBA в `OUT_DIR/window.rgba`, в коде —
  `include_bytes!(concat!(env!("OUT_DIR"), "/window.rgba"))`. Так новая зависимость не появляется.

Тест: значок 256 × 256, центр непрозрачен, угол прозрачен.

**Знак в интерфейсе** (`src/ui/mark.rs` или `src/mark.rs`):

- `paint(painter, rect)` рисует плитку и знак по координатам мелкого SVG (числа скопированы вместе со сдвигом
  центровки); цвета фиксированные и от темы не зависят;
- `app_mark(ui, size)`, `brand(ui, name)` (28 px в шапке), `about(ctx, open, info, status)` с знаком 56 px;
- `about` — копия `chrome::about` из частей набора (`chrome::dialog`, `widgets::button`, `widgets::note`,
  `anvil_ui::tr`): набор рисует там значок из `AppInfo.icon`, и подменить его нельзя. Поле `AppInfo.icon` остаётся
  с любым значком набора — оно не показывается. API этих функций в `kit-v0.2.0` и `kit-v0.4.0` совпадает;
- округлять углы у треугольников нет смысла: на 28 px радиус меньше пикселя.

**Трей** (Morok) — два значка одним размером 32 px из файлов: «подключено» — знак на плитке, «не подключено» —
контур плитки и серый знак `#8C96AE` без заливки (`morok-tray-off.svg`). Они различаются формой, а не только
цветом. Красная точка-предупреждение дорисовывается кодом в правом нижнем углу и ложится на финальную точку знака.

**Уведомления** — PNG 128 px (`include_bytes!`), которое кладут рядом с настройками для тоста Windows.

**Версия.** Значок — «мелкое изменение внутри этапа»: третья цифра (`0.1.0 → 0.1.1`), номер называют в отчёте.
Если в чужой сессии версия уже поднята, свою не трогают и говорят об этом.

## 8. Особые случаи

**Anvil.** Значок окна, exe, трея и уведомлений — готовые PNG в `crates/anvil/assets/icon`; `build.rs`
декодирует их, собирает `.ico` из семи кадров (16–32 — упрощённый знак, от 48 — полный) и кладёт в `OUT_DIR` сырые
RGBA для окна и трея и PNG для тостов. В интерфейсе знак Anvil — квадрат `VIOLET` со значком `Hive` из набора.

**Amber.** Значки рисует код `crates/amber-desktop/src/icon.rs`: PNG через `include_bytes!`, красная точка
«непрочитанное» дорисовывается. Центр — свой значок `amber-admin` (стопка серверов в том же материале, готовый
`window-64.rgba`). Значок у exe — `winresource` в двух крейтах, `.ico` собирается скриптом из PNG. Телефон —
адаптивный значок: `ic_launcher_background`, `ic_launcher_foreground`, `ic_launcher_monochrome` (векторные
drawable, безопасная зона 66 dp из 108) и `ic_notification` 24 dp; проверка — `:app:processDebugResources`.
Правила Amber: exe в `target/release` и APK **не пересобирают** без слова «пересобери»; проверки — в `target/ui` в
отдельном worktree; проект не отформатирован rustfmt — `cargo fmt` по всему проекту не гонять.

**Morok.** Репозиторий закрытый; выпуски — в публичный `morok-releases` (позже). Значок лежит в `assets/brand`,
изменение OpenSpec `morok-logo` переписано под выбор владельца.

## 9. Проверка

1. `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` — зелёные. Если проект уже не
   отформатирован (Amber), `cargo fmt` гоняют по своим файлам.
2. **Снимки окна в обеих темах и на RU и EN.** Через `PrintWindow` с флагом 2 (не `CopyFromScreen`). Тему и язык
   задают файлом настроек программы:
   - Tetrachrome: `settings.json` рядом с `presets.json`, `{"common":{"theme":"dark","language":"ru"}}`;
   - FFMincer: `%APPDATA%\FFMincer\config.txt` — **настоящий конфиг владельца**: копия, свой временный, возврат,
     сравнить хэш;
   - Morok: `morok-desktop.exe --screenshot <папка> --scene on --theme dark --lang ru`.
   Файл настроек пишут **без BOM** (`WriteAllText` с `UTF8Encoding($false)`): `Set-Content -Encoding utf8`
   в PowerShell 5.1 добавляет BOM, и `serde_json` файл не читает — тема тихо остаётся по умолчанию.
3. **«О программе»**: на один прогон ставят `about_open: true` (в конструкторе `App`), снимают окно, возвращают
   файл из копии и проверяют, что `git diff` пуст.
4. **Значок exe**: `System.Drawing.Icon.ExtractAssociatedIcon(exe)` и пиксель знака; `FileVersion` из версии
   пакета.
5. **Трей**: смоделировать 32 px в масштабе на тёмной и светлой панели, с точкой и без.
6. Скрипт рендера второй раз — те же хэши.

## 10. Git и параллельные сессии

- Перед началом: `git status`, `git worktree list`, план другой сессии на странице хода работы. Если в дереве
  чужие несохранённые правки (Morok, FFMincer), значок делают в **отдельной копии**
  (`git worktree add -b icon-… ../<папка> HEAD`), своя `target` в ней; общий `target` не занимают.
- Слияние — после коммита другой сессии: `git rebase main`, повторная проверка, `git merge --ff-only`, затем
  `git worktree remove` и удаление ветки. Конфликты обычно в `Cargo.toml` (build-зависимости) и `HANDOFF.md`
  (оставить оба раздела).
- Коммитят только свои пути, сообщение по-английски, в конце — строка соавторства.
- Страница хода работы называется по проекту: `progress.py plan` и `finish` **затирают чужой план** того же
  имени. Перед `plan` смотрят `~/.claude/progress/<проект>.json`; если чужой план есть — не запускают свой под тем
  же именем и не вызывают `finish`.
- Публичные репозитории (Anvil, Tetrachrome, FFMincer): пуш, тег, выпуск — только по слову; закрытый Morok —
  так же. Когда пуш в `main` нельзя (чужая работа в дереве), ветку публикуют под своим именем и говорят об этом.
- Репозитории на Windows с `autocrlf`: рабочие файлы в CRLF, в индексе LF; предупреждения «LF will be replaced by
  CRLF» безвредны. Правя файлы скриптом, читают и пишут байты и возвращают CRLF, иначе `git diff` покажет весь файл.

## 11. Инструменты и грабли (Windows)

- **Растеризатор** — `resvg` (`scoop install resvg`), запуск: `resvg -w 256 -h 256 in.svg out.png`. Скиллы
  `icon-brief`, `icon-draw`, `icon-critique`, `icon-export` запускают скрипты с `PYTHONUTF8=1` (иначе
  `UnicodeEncodeError` на «→»); `icon-draw` умеет только строгий минимализм — для остального стиль задают вручную.
- Варианты рисуют скриптами на Python, которые пишут SVG; лист сравнения собирается одним SVG и растеризуется.
  Подписи на листе — шрифтом Segoe UI; `resvg` предупреждает о подмене шрифта, на значки это не влияет.
- `sleep` в Bash блокируется — ждать циклом `until` в фоне; `du` по `target` на USB-диске (E:) висит минутами;
  сборки на E: долгие, диск D: — NVMe, его от износа берегут (`debug = "line-tables-only"`, чистить `target`).
- Многострочный Python в heredoc Bash съедает `\\`: путь Windows и `\r` превращаются в управляющие знаки. Файлы
  пишут инструментом записи или собирают обратный слэш как `chr(92)`.
- Сборки — в фон с логом, потом ждать завершения; в рабочей сессии на странице хода работы ничего не открывают.
- Цвет «на глаз» — по палитре программы, а не по чистому RGB: цвета каналов Tetrachrome взяты из `src/theme.rs`.
