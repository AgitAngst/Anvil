# Соглашение о выпусках

Как выпускаются программы семьи Anvil. На это опираются `anvil-update` (проверка и установка
обновлений изнутри программы), Anvil (установка и выпуск из окна) и общий workflow выпуска.

## Коротко

| Что | Как |
|---|---|
| Тег | `vX.Y.Z`, пред-выпуск — `vX.Y.Z-beta.N` (`-rc.N`, `-alpha.N`) |
| Версия в `Cargo.toml` | та же `X.Y.Z` — её программа знает о себе (`env!("CARGO_PKG_VERSION")`) |
| Архив под Windows | `<app>-X.Y.Z-windows-x64.zip`: exe и всё, что ему нужно, в корне архива |
| Контрольные суммы | `SHA256SUMS` в каждом выпуске: строка `<sha256>  <имя файла>` на файл |
| Заметки | тело GitHub Release — их показывает «Что нового» |
| Где | GitHub Releases репозитория программы; закрытый код — отдельный публичный `<app>-releases` |

## Подробно

**Тег и версия.** Тег ставится на коммит, где версия в `Cargo.toml` уже поднята. Проверка
обновлений сравнивает версии по semver: `0.3.1 > 0.3.0`, `1.0.0 > 1.0.0-rc.1`. Пред-выпуски
предлагаются только тем, кто включил «Предлагать пред-выпуски». Тег без `v` или не из трёх чисел
выпуском не считается.

**Архив.** Имя строго `<app>-<версия>-windows-x64.zip`, `<app>` — то, что программа передаёт в
`anvil_update::Config::new`. Файлы — в корне архива (одна общая папка верхнего уровня тоже
допустима: её снимут при распаковке). В архиве обязательно лежит exe с тем же именем, что у
запущенной программы, — иначе обновление не ставится.

**`SHA256SUMS`.** Без него `anvil-update` обновление не поставит: непроверенный файл хуже старой
версии. Формат как у `sha256sum`:

```
3f5c…9a1e  amber-desktop-0.3.1-windows-x64.zip
```

**Заметки.** Тело Release, обычный Markdown. «Что нового» показывает заголовки, списки и абзацы.
Общий workflow берёт заметки из аннотации тега, а без неё — список изменений, который собирает
GitHub. Тег с заметками ставить так, иначе git вырежет строки с `#` (заголовки) как комментарии:

```sh
git tag -a v0.3.1 --cleanup=verbatim -F notes.md
```

**Несколько программ в одном репозитории** (Amber: клиент, сервер, админка) — отдельный архив
на каждую, со своим `<app>`: `amber-desktop-0.3.1-windows-x64.zip`, `amber-admin-0.3.1-windows-x64.zip`.
`SHA256SUMS` — общий, по строке на архив.

**Закрытый код.** Приватные Releases без токена не видны, поэтому выпуски такой программы
публикуются в отдельный публичный репозиторий `<app>-releases` (для Amber — `AgitAngst/amber-releases`).
Код остаётся закрытым, CI закрытого репозитория публикует туда выпуск токеном с правом записи
(секрет `RELEASES_TOKEN`). В репозитории выпусков должен быть хотя бы один коммит (README).

## Как устроено обновление

1. Программа при запуске и раз в сутки (если это включено) спрашивает список выпусков.
2. Нашёлся выпуск новее — ненавязчивый баннер: «Вышла vX · Обновить · Что нового · Позже ·
   Пропустить эту версию». Модальных окон при запуске нет.
3. «Обновить»: скачать архив → сверить SHA-256 → распаковать рядом → поставить:
   - **портативная копия** (exe где угодно): новые файлы на место старых, старые переименовываются
     в `имя.old-<время>` (запущенный exe Windows переименовать разрешает), уборка — при следующем запуске;
   - **установка Anvil'ом**: `…\<app>\versions\<версия>\` и junction `…\<app>\current` на активную;
     новая версия ставится рядом, `current` переключается, прежние остаются для отката.
4. «Перезапустить» — новая версия запускается с теми же аргументами, старая закрывается.

Что бы ни сломалось по дороге (сеть, сумма, место на диске), рабочей остаётся старая версия.

## Общий workflow

`.github/workflows/rust-release.yml` в репозитории Anvil — многоразовый: собирает бинарники под
Windows, упаковывает по соглашению, считает `SHA256SUMS` и публикует Release. В программе:

```yaml
# .github/workflows/release.yml
name: Release
on:
  push:
    tags: ["v*"]
permissions:
  contents: write
jobs:
  release:
    uses: AgitAngst/Anvil/.github/workflows/rust-release.yml@kit-v0.1.0
    with:
      app: tetrachrome
      bins: tetrachrome
```

Входы: `app` — начало имени архива; `bins` — бинарники через пробел; `package` — пакет cargo, если
бинарники не в корневом; `repository` — куда публиковать (`owner/name`), пусто — сюда же.
Для закрытого кода — ещё `secrets: RELEASES_TOKEN: ${{ secrets.RELEASES_TOKEN }}`.
