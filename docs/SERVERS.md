# Серверы: установка и управление модулями

Версия приложения: 1.2.1. Описано по коду на 29.10.2026. Ядро — крейт `crates/anvil-servers` (без графики),
вид — `crates/anvil`, модуль `servers.rs` и `ui/servers.rs`.

Центр ставит серверы программ на Linux-машины по SSH и управляет ими. Что именно ставится, описывает **модуль** —
манифест TOML; код центра не знает ни одного сервера по имени.

## Что нужно

- Машина с Linux, systemd, x86_64 или ARM64, SSH-доступ (root или пользователь с `sudo`; при входе по ключу — `sudo`
  без пароля).
- Выпуск сервера на GitHub: файл по архитектуре и `SHA256SUMS`.
- Пароли и ключевые фразы центр хранит только в хранилище учётных данных Windows (служба `anvil-servers`), в `anvil.toml`
  их нет.

## Безопасность

- До подтверждения отпечатка ключа машины центр ничего не посылает, в том числе пароль. Ключ сменился — отказ и
  отдельное окно; пароль в этот момент не отправлен.
- Всё, что центр запускает сверх команд контракта (действия, консоль, удаление), показывается дословно и подтверждается.
- Токены в «Ходе работы» скрыты (`token=…`, `"token": "…"`, `Bearer …`, токены GitHub).
- Нет `SHA256SUMS` в выпуске — центр останавливается и спрашивает; не сошлась сумма — отказ всегда.

## Контракт сервера

Бинарник сервера умеет:

| Команда | Что делает |
|---|---|
| `install [поля формы]` | ставит или обновляет: пользователь, каталог, служба, порт, сертификат; повтор безопасен — данные остаются |
| `status --json` | печатает объект: `name`, `version`, `running`, `address`, `fingerprint` и любые свои поля; известные центр показывает карточкой, остальные — строками «ещё» (ключи с `token`, `password`, `secret`, `passphrase` скрыты) |
| `backup --to ПАПКА` | согласованный снимок данных |
| `uninstall` | убирает службу и бинарник |

## Манифест модуля

Файл `<папка настроек Anvil>/modules/*.toml` или встроенный (`crates/anvil-servers/src/builtin.rs`).

```toml
id = "example"                  # обязательно: строчные латинские буквы, цифры, дефис
name = "Пример"
hidden = false                  # true — виден только при включённом «Скрытые модули»
instances = false               # true — несколько экземпляров на машине (<служба>-<имя>)
service = "example"             # служба systemd; по умолчанию = id
binary = "/opt/example/example-server"   # обязателен, если где-то есть {bin}
# необязательно: user, data_dir (по умолчанию = служба и /var/lib/<служба>), icon

[source]                        # обязательно
repo = "owner/example"          # выпуск GitHub
assets = { x86_64 = "example-server", arm64 = "example-server-arm64" }
checksums = "SHA256SUMS"
tag_prefix = "server-v"         # необязательно: в репозитории есть и другие выпуски (приложение)

[ports]
tcp = [8740]

[commands]                      # install обязательна
install = "{bin} install {args}"
status = "{bin} status --json"
backup = "{bin} backup --to {dir}"
uninstall = "{bin} uninstall"

[[form]]                        # поля окна установки: text | password | number | port | bool | choice
key = "port"
label = "Порт"
kind = "port"
default = 8740
arg = "--port {value}"

[[action]]                      # кнопки «Обслуживания»; confirm по умолчанию true
label = "Перезапустить"
cmd = "systemctl restart {service}"
confirm = true
```

- Выпуск берётся последний (`releases/latest`). Если в репозитории рядом выпуски приложения, `tag_prefix` задаёт начало
  тега сервера: берётся новейший опубликованный выпуск (не черновик и не пред-выпуск) с таким тегом из последних 50.
- Подстановки: `{bin}`, `{args}` (поля формы), `{service}`, `{dir}`, `{instance}`, `{user}`; `{{` и `}}` — сами скобки. Незнакомое
  имя — ошибка при разборе. Значения формы проверяются по виду поля (текст не начинается с `-` и без управляющих знаков)
  и подставляются как слова оболочки.
- Без обязательного поля манифест не принимается; в списке он остаётся с причиной (`no install command (commands.install)`).
  Дубль `id`: встроенный выигрывает у файла, первый файл по алфавиту — у второго.
- Скрытый модуль (в том числе скрытый битый файл) виден, только пока переключатель «Скрытые модули» в настройках включён.
- Экземпляры (`instances = true`): у каждого своя служба, пользователь, каталог и порты; занятый порт (свой у другого
  экземпляра или слушаемый машиной по `ss -H -ltun`) форма не принимает.

## Вид «Серверы»

Меню «Другие виды» в Кузнице или палитра `Ctrl+K`. Слева — машины (точка состояния, имя, адрес, число модулей) и «+»; справа
открытая машина: шапка (имя, состояние, «Поставить сервер…», «Проверить», «Ещё» — изменить или убрать из списка), карточки
установленных модулей и вкладки «Обзор / Обслуживание / Журнал / Консоль». Внизу — «Ход работы» (до 400 строк на машину,
«Скопировать»). «Парк серверов» остаётся отдельным видом — проверка порта и ваши команды.

- **Новая машина:** адрес, название, логин, способ входа (пароль / файл ключа / ssh-agent), порт SSH. Пароль и фраза — в
  хранилище учётных данных. Дальше окно «Первое подключение» с отпечатком ключа; сменился — «Ключ машины сменился».
- **Проверка** (кнопка «Проверить», автоматически при открытии вида её нет): ключ → архитектура → для каждого модуля из реестра
  `status --json`. Экземпляры, созданные не через Anvil, не находятся: центр читает основной сервер и экземпляры из своего кэша.
- **Установка:** архитектура → файл выпуска (токен GitHub — из хранилища серверов, иначе тот, что уже есть у Anvil; нет `SHA256SUMS` —
  вопрос владельцу) → временный каталог на машине (`mktemp -d`) → заливка → `install` от root с полями формы (порты сверяются
  по `ss`) → уборка каталога, в том числе после ошибки → `status`. В `{bin}` команд `install` и `update` — загруженный файл;
  остальные команды идут на установленный путь.
- **Обновление:** команда `update` манифеста, если она есть, иначе `install`; порты не сверяются.
- **Обслуживание:** запуск, остановка, перезапуск и журнал (`journalctl -u <служба> -n N --no-pager`) идут без окна —
  команда видна в «Ходе работы»; действия манифеста — с подтверждением, если `confirm` (по умолчанию да); консоль — всегда с
  подтверждением; удаление — всегда с вводом имени. Копия кладётся на самой машине в `/var/backups/anvil/<служба>-<время>` и
  на ПК не скачивается.
- **Настройки (Кузница → Серверы):** «Скрытые модули» (по умолчанию выключен; скрытые модули при выключенном переключателе не
  опрашиваются и не показываются), папка `modules/` рядом с настройками, список манифестов, которые не приняты, с причиной.
- **Хранение:** машины — `[[servers]]` в `anvil.toml` (id, имя, адрес, порт, логин, способ входа, подтверждённый отпечаток), без
  секретов.

## Проверка

`cargo test -p anvil -p anvil-servers`; SSH проверен тестовым SSH-сервером в процессе, цепочки шагов — на подставных
`Remote` и `Releaser`. Живой VPS, вход по файлу ключа, настоящий ssh-agent и скачивание с GitHub не проверялись.
