# Design

## Решения

1. **Хранение — в данных контекста egui** (`ctx.data`, временные, по `Id`), как акцент (`theme::accent`). Палитра
   `Palette` — `Copy`, поэтому кладётся как есть.
2. **`Palette::of_ctx`** сначала смотрит подмену; нет — `Palette::new(тема, акцент)` как раньше. Все виджеты набора берут
   палитру только через `of`/`of_ctx` — отдельных мест, где собирается `Palette::new` для рисования, нет (кроме
   `chrome::clear_color`, у него появляется пара `clear_color_of`).
3. **Стиль egui.** `theme::apply` получает необязательную палитру: если она есть, `Visuals` строится из неё (основа
   `Visuals::dark()` или `light()` — по `palette.dark`), а не из таблицы. `set_accent` и `set_palette_override` обе вызывают
   одну пересборку стилей обеих тем — порядок вызовов не важен.
4. **Тема.** Подмена задаёт цвета целиком и для обеих тем: `Palette::dark` решает, тёмная ли основа стиля. Выбор
   темы (`choose`) подмену не снимает; программа сама ставит тему по `Palette::dark`, как Kamerton.
5. **Не в наборе.** Чтение цветов высокого контраста Windows и сборка палитры из них — дело программы: они зависят от
   системы. Набор даёт только место для чужой палитры.
6. **Тест контраста** (`every_text_reads_on_its_background`) относится к таблице набора и подмену не проверяет:
   читаемость чужой палитры — забота того, кто её подаёт (системные цвета высокого контраста читаются по определению).
