# Design

## Context

Логика и соглашение — `crates/anvil-update` и `docs/RELEASES.md` («Лимит запросов GitHub», «Как устроено
обновление»). Правила Android — `docs/ANDROID.md` §2, §6. Набор 0.1.0 уже даёт тему, настройки и «О программе».

## Goals / Non-Goals

**Goals:** то же поведение, что у `anvil-update` (выбор выпуска, пред-выпуски, пропуск, обход лимита, SHA-256),
установка через систему, готовый вид на Compose.

**Non-Goals:** обновление в обход подтверждения системы, фоновые проверки по расписанию (`WorkManager`) — только при
запуске и по кнопке; сборки `rustore` и `play` (у них обновляет магазин).

## Decisions

- **Отдельный модуль `anvil-update`** — как на ПК: разрешения `INTERNET` и `REQUEST_INSTALL_PACKAGES` попадают в
  программу только вместе с ним, программа берёт его зависимостью сборки `github` (`githubImplementation`).
- **Без новых библиотек.** Сеть — `HttpURLConnection` (таймаут 60 с, `User-Agent: anvil-update-android/<версия>`);
  JSON — небольшой свой разбор (`MiniJson`), чтобы и тесты на JVM шли без Android; потоки — корутины, они уже
  приходят с Compose.
- **Версии** — перенос `version.rs` (semver с пред-выпусками), выбор — перенос `releases::choose`, имя файла —
  `<app>-X.Y.Z-android.apk`.
- **Ошибки** — `sealed class UpdateError` (лимит с минутами, HTTP, сеть, нет APK, нет `SHA256SUMS`, сумма, место,
  установка); текст на языке программы — из ресурсов модуля.
- **Состояние** — `Updater.state` (наблюдаемое Compose): нет проверки, проверка, актуально, есть обновление,
  скачивание (байты из байтов), готово к установке, нужно разрешение, установка, ошибка. «Позже» и пропуск, время
  последней проверки, флажок пред-выпусков — в `SharedPreferences` `anvil` (как у набора).
- **Скачивание** — в `cacheDir/anvil-update/`, старые файлы удаляются перед новым скачиванием и после установки.
- **Установка** — сессия `PackageInstaller`; статус приходит в свой `BroadcastReceiver` (не экспортирован):
  `STATUS_PENDING_USER_ACTION` — открыть окно подтверждения системы; ошибка — в состояние. После установки система
  перезапускает программу сама; при следующем запуске «установлено» узнаётся по сохранённой версии.

## Risks / Trade-offs

- [Оболочки Xiaomi и других требуют своих разрешений на установку] → ошибка установщика показывается текстом системы;
  проверка — на телефоне владельца.
- [Без своего выпуска APK живую установку не проверить] → логика проверена тестами на образцах ответов GitHub;
  живое скачивание и установка — на первом выпуске Ampulse.
- [Свой разбор JSON] → только то, что отдаёт GitHub (объекты, массивы, строки с экранированием, числа, логические);
  покрыт тестами.
