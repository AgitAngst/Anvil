## Why

Владелец (28.10.2026, план эволюции Anvil, этап 1): проекты должны подключаться сами и вручную. Сейчас Anvil ищет проекты
только в папках из настроек, а токен GitHub используется лишь для CI и выпусков. Нет ни списка репозиториев аккаунта,
ни клонирования, ни пометки «публичный/закрытый» — а она нужна следующим этапам (страж правил, бюджет CI, каталог).

## What Changes

- Окно «Добавить проект» (кнопка в боковой панели и в палитре): вкладки «С GitHub», «Папка», «Адрес».
  - «С GitHub»: репозитории аккаунта по токену из хранилища Windows (владелец и организации), с пометкой публичный/закрытый,
    «Подключён», «Есть на диске» (по origin), «Клонировать». Репозитории, уже лежащие в папках поиска, подключаются сами.
  - «Папка»: любая папка с проектом, не только корень поиска (добавляется в `roots`).
  - «Адрес»: `https://github.com/owner/name` или `owner/name` — клонирование в папку клонов (по умолчанию первая из папок поиска).
- Автоподключение: при запуске и по кнопке «Обновить список» Anvil спрашивает у GitHub список репозиториев и показывает новые
  (чип «Новых: N»); клонировать автоматически он не клонирует — только по кнопке.
- Метка видимости `public` / `private` у каждого проекта с origin на GitHub: из API (`private`), с ручной подменой в настройках проекта.
- Версия приложения 0.4.0 (набор не меняется).

## Non-goals

Автоклонирование без кнопки; GitLab и прочие хостинги; вход через OAuth (остаётся свой токен); показ метки в других
местах, кроме списка и шапки проекта (страж правил использует её в этапе 3).

## Impact

`crates/anvil`: `config.rs` (`clone_dir`, `ProjectSettings::visibility`), `github.rs` (список репозиториев, видимость),
новый `sources.rs` (клонирование, сопоставление), `ui/add_project.rs`, `ui/sidebar.rs`, `ui/palette.rs`, `lang/en.tsv`,
`docs/`, `HANDOFF.md`, `SPEC.md`.
